## passphrase 是什么

passphrase 是你在助记词之外再加的一道**口令**，是**第二道锁**。

规则只有一条：

> 同一组助记词 + 不同的 passphrase = 完全不同的钱包

这意味着两件事：

1. 如果你输错 passphrase，钱包软件不会报错，只会打开一个新的空钱包。
2. 丢了 passphrase，等于丢了币。

## 它比你想象的容易破解

BIP39 标准规定：用 passphrase 派生私钥时，PBKDF2 只有 **2048 轮**迭代。

2048 是个刻意偏小的数字——为的是让性能有限的硬件钱包也能在一秒内算完。代价是：一旦攻击者知道 / 猜到 seed，测试候选 passphrase 同样便宜。一块普通显卡，每秒可以完成**数万次**完整猜测。

| passphrase 类型 | 大致熵 | 攻击者拿到助记词后 |
|---|---|---|
| 姓名缩写 + 生日 | 约 20 bit | 几分钟内破解 |
| 一句歌词、台词、名言 | 约 25 bit | 早已被字典收录，同样快 |
| 4 个随机单词 | 约 44 bit | 有决心的攻击者耗得起 |
| 6 个随机单词 | 约 66 bit | 现有算力下安全 |

所以，不要觉得给一套低熵的助记词加上一个复杂点的 passphrase 就安全了，**我们的主要防线还是在助记词上**。

**助记词是主锁、是大锁，passphrase 是附锁、是小锁。**

> **备注**：这句话我纠结要不要写上——理论上它并不正确，passphrase 完全可以设置得比助记词的熵还高。但我还是想提醒那些「设置一个较复杂的 passphrase，就敢用手机钱包生成的助记词保存大量资产」的人：高随机性的助记词才是我们的主要防线。

## 我们如何使用 passphrase

那么问题来了：你主要防谁？

你的助记词是**投骰子生成的**、从未触网，黑客想暴力破解需要花费全宇宙的能量。真正可能发生的场景是：

1. **来家里的人**——亲戚、朋友、室友、家政、维修工、搬家公司，看到了你的备份；
2. **5 美元扳手攻击**——有人当面胁迫你交出钱包。

所以你要对抗的不是 GPU 集群，而是**认识你的人的想象力**。这会改变设计目标：

> 不必对抗全世界的算力，只需对抗认识你的人的猜测——设计应该向「记得住」倾斜。

网上流行的「6 个以上随机单词」是对抗 GPU 集群的配置，代价是你根本记不住，只能把它存在某个地方，而存储本身就是新的风险和负担。助记词越干净（掷骰子、不触网），就越有资格把 passphrase 设计得好记。

我的建议是：

1. 务必使用 passphrase，且**seeds** 下不存币。（根据2026年coldcard事件，助记词下存少量币做哨兵钱包只会告诉黑客“此地无银三百两”，只会告诉黑客这里值得投入算力破解passphrase）
2. 确保主要防线助记词是掷骰子生成的，则passphrase的设计以确保不忘记为原则。可以使用常用 App 或银行卡等常用密码作为 passphrase ，且每隔一段时间演练恢复，因为如果长期不用，人类必定遗忘。

## passphrase 重点清单

- **大小写敏感，空格也是内容**。`Kiwi iron` 和 `kiwi  iron` 是两个钱包，过渡期的纸条务必原样照抄。
- **输错不会报错**。错一个字母，钱包照样打开一个全新的空钱包。所以「余额消失了」先别慌——十有八九是 passphrase 敲错了，逐个字符回放一遍再试。
- **和助记词分开存放**。拿到两者才等于拿到币，写在一起等于白设。
- **先演练，再存大钱**。设好 passphrase 后，用一笔小额做完整的恢复演练：清空钱包，凭记忆和备份恢复，确认拼写无误，再转入大额资金。

> 很多人设计passphrase喜欢使用「姓名缩写 + 生日」。建议您别这样设计。
